# 人物追踪工程、性能与原生高清验证

日期：2026-10-10。基线提交 `7e8265f50985c29810e4ca21fbbad85d145025bf`，本次改动尚未提交或推送。Windows 本地执行，AWS 只做 `nba / us-east-1` 的 STS 身份检查；没有新增付费模型调用、训练、云资源、部署或平台评测。

## 结果与采用范围

完成了公平的关联候选比较、CPU ONNX 数值/速度对照、连续 ID 标注与 TrackEval 工具、原生 1080p 带框/数据/中文音轨工程样片。用户后来提供的两份粗标用于减少多余人物，另见[球员筛选记录](../coarse-player-tuning-20261010/README.md)。独立精度、ID 连续性、第三段泛化和云端性能尚未通过。

默认仍为 YOLO11m / PyTorch / 960 / BoT-SORT / ReID 关闭。ByteTrack、ONNX、640 输入和 15 Hz 都是显式实验候选，没有因速度更快而自动替换生产默认值。已登记粗标的视频会额外应用带来源哈希的临时球员视图；未登记的新视频仍可走通用追踪。

## 同一检测缓存的 A/B/C

串行运行，固定视频、原始检测、场地筛选、PTS、2 个 Torch 线程与当前 `fuse_score=false`。ReID 修复了同一帧高/低分关联阶段覆盖特征池的问题，记录实际编码和复用次数；跨切镜不复用身份。

| 视频 | A BoT-SORT | B ByteTrack | C BoT-SORT＋ReID | A/B/C 匿名轨迹数 |
| --- | ---: | ---: | ---: | --- |
| 阿门 | 9.455 秒 | 5.028 秒 | 60.882 秒 | 79 / 82 / 78 |
| 弗拉格 | 11.457 秒 | 6.704 秒 | 54.710 秒 | 90 / 91 / 89 |

这是缓存命中的追踪工具墙钟，排除首次检测、语音、作品编码和模型服务，不是整任务时延。轨迹更少不证明串人减少。缺少确认的连续人工 ID，因此保留 A；B 留作加速候选，C 未进入默认链路。[完整配置、缓存和资源证据](association-comparison.json)

增加了候选比较的 `requireCacheHit`：检测来源不符时拒绝，而不是静默重新推理。公平实验显式关闭视频专用粗标筛选，避免把标注辅助结果当成通用追踪收益。

## ONNX 与输入频率实验

同一 YOLO11m FP32 权重、同一 24 个真实源帧和固定张量形状，Torch/ONNX 共用 letterbox、RGB 转换、坐标还原和 NMS。ORT 使用 CPUExecutionProvider、intra-op 2 / inter-op 1；Torch 为 2 个推理线程。单库线程限制不等于整机只占 2 vCPU。

| 960 输入 | Torch 热推理中位数 | ONNX 热推理中位数 | 中位数加速比 |
| --- | ---: | ---: | ---: |
| 阿门 | 0.450506 秒 | 0.376166 秒 | 1.198 倍 |
| 弗拉格 | 0.495799 秒 | 0.371898 秒 | 1.333 倍 |

两片的后处理框无未匹配项，匹配 IoU 最低约 0.999986，分数差最大约 0.00000262。它验证抽样数值一致性，不是人工精度。640 输入单独比较约为 1.25–1.31 倍；不能把不同尺寸混作后端收益。[960 对照](backend-comparison-960.json)、[640 对照](backend-comparison-640.json)

原生阿门视频前 5 秒，按顺序固定后端后调整尺寸，再固定尺寸调整频率，全部缓存未命中：

| ONNX 配置 | 实测检测帧 | 工具墙钟 | 采样峰值 RSS |
| --- | ---: | ---: | ---: |
| 960 / 原帧频率 | 300 | 126.145 秒 | 约 780 MB |
| 640 / 原帧频率 | 300 | 63.445 秒 | 约 582 MB |
| 640 / 15 Hz | 75 | 17.842 秒 | 约 582 MB |

低频候选没有补框或插值，只展示实际源帧曝光，可能闪烁；尚未验证远处球员召回和 IDF1，不采用为默认。5 秒本机结果不能证明“60 秒视频 8 分钟”或 AWS/ARM64 达标。[逐阶段和缓存证据](native-performance.json)

实验发现旧 `pts-greedy-v1` 在原生 59.94 fps 的微小 PTS 抖动下只处理 151/300 帧。新增显式 `pts-grid-v2`，足够高的上限保留每个解码帧，低频按锚定时间网格取实际帧；缓存版本独立，旧默认/缓存未静默改变。151 帧失败候选保留在台账，不当作原帧基线。

首次 640 导出暴露 Ultralytics 导出目标路径碰撞：只覆盖了本地实验 ONNX，没有改动 PT 或视频。已改为隔离目录导出、目标存在时拒绝覆盖，并增加回归检查。[初始、当前模型哈希与修复说明](model-exports.json)。初始 960 与重新导出文件元数据不同，报告保留各次实际哈希，不混用。

## 连续 ID 评估工具

新增 `tracking_eval.py`：从真实源帧和校验过的检测来源建立各 5 秒 / 10 Hz / 50 帧的空白标注页。可标注人工 H 编号、遮挡、逐帧确认和标注者；编辑后撤销当前帧确认。未全部核对、来源不符或没有人工 ID 就拒绝出指标。

确认后的评估通过 TrackEval 1.3.0 的 HOTA、Identity、CLEAR 计算，并导出 MOT 文件、源帧/PTS 映射和哈希。当前连续协议评估全部尺寸合格人物观测，包含场外观测；用户离散球员粗标属于另一口径，不能直接作为此协议的 GT。指标范围通常为 0–1，ID 切换为计数，MOTA 可为负值。

合成完美/身份切换样例只验证计算行为，不是两段视频的精度证据。标注 UI 导出测试明确记为 `NOT GROUND TRUTH`，不纳入评估。[UI 验证](ui-verification.json)。TrackEval 可选 BURST 依赖缺失警告不影响已实际执行的二维指标测试；未安装无关依赖。

## 原生高清工程成片

`FILM_RESOLUTION=source` 仅在已核验显示平面为 16:9、尺寸不超过 1920×1080 时使用原生画布；默认仍为 720p。ASS 保持统一 1280×720 坐标并等比缩放，不上采样制造号码证据。编码使用视频流的源时间基准及 passthrough，音频独立处理。

最终工程作品 ID `18878f99-b53c-40ff-afde-c83d2d258037`：1920×1080、59.94 fps、5 秒、300 帧、SAR=1，与原片前 300 帧相对 PTS 最大差为 0。中文音轨非空，Edge 实际播放并解码音频。[独立验证](native-hd-validation.json)、[成片帧](native-hd-frame.png)

该样片解说为“这是原生高清成片工程验证”，数据卡仅显示实测视频帧数/帧率，不冒充 NBA 指标或新模型解说。它验证高清工程链路；不是完整比赛 AI 高清作品，也没有证明每个球员框正确。早期字幕数字截断和音频 time-base 错误已修复，历史失败文件保留在私有目录。
