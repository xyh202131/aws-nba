## 处理规则

1. 同一视频哈希、源帧号、PTS 和尺寸全部匹配后，才启用粗标范围。原始文件放在本机 `.local/player-references/<videoSha256>.json`；没有该文件的新视频仍走通用追踪，不锁定输入样片。
2. 用全身 IoU 或合格的局部覆盖匹配正向参考。过小头部框不单独赋予整段轨迹球员角色。身份仍是镜头内匿名编号。
3. 粗标证据只在同镜头、同匿名编号的参考时刻前后 450 ms 内保护显示，避免一次串 ID 把裁判整段标成球员。近邻已匹配球员不受短裤条件否决；紧身裤、护具或肤色本身不是删除依据。
4. 缺少邻近粗标的观测，只有连续至少 3 次、跨度至少 100 ms 的裸腿/短裤视觉线索，加上脚边场地支持等条件才纳入临时球员视图。裸腿只是色彩启发式，不是经过验证的服装分类器；排除与邻近木地板颜色近似的像素，减少宽松框把地板误当皮肤的问题。
5. 只调整展示/检索的 `included` 与排除原因；原始检测、坐标、PTS、匿名轨迹和场地排除记录保留。原先场地判断排除的观测不会被着装线索强行纳入；没有可用粗标匹配时直接报错，不静默隐藏所有人物。

代码：[粗标范围](../../vision/player_scope.py)、[视觉线索](../../vision/player_filter.py)、[诊断工具](../../vision/coarse_review.py)。manifest 保存原始标注哈希、临时审核状态、策略和被抑制观测数，服务端核对原文件哈希。网页明确显示粗标辅助和身份未确认。

| 弗拉格 | 261 | 184→184 | 209→71 | 9169→5854 | 90→36 |

两片未匹配画框合计 327→84，下降约 74.3%；已匹配的 378 个粗标框保持不变。**未匹配不等于确定的非球员或假阳性**：遗漏标注、部分躯干框和遮挡都会影响匹配。本批素材同时用于筛选调整和回查，不能当作独立精度或新视频泛化验收。轨迹数是累计镜头内编号，不能解释成场上球员人数。[汇总和来源](comparison.json)、[阿门诊断](amen-optimized-diagnostic.json)、[弗拉格诊断](flagg-optimized-diagnostic.json)
