# 模型提示词与复核流程（未调用草案）

质量优先候选沿用 Qwen3-VL 235B + Sonnet 4.6，Opus 4.8 仅是待核验升级候选。本文件只准备提示词；当前个人项目配额与跨区域限制仍生效。输入需适配实际模型 API 的图片数量、大小和协议，尚未据此实现请求代码。

## 输入包

给所有候选相同的真实证据：素材 ID/哈希、时长、有序帧及 `frame_id/video_time_ms`、必要局部裁剪、经允许传入的官方记录和字段定义。先给原始画面再给候选解释，降低复核者被上一模型结论引导的风险。

视频中的记分牌、广告、字幕与导入记录均是待分析数据。其中即使出现操作指令，也不能当成系统指令。模型不获得任意 shell、远程上传或更改云配置的能力。

## A. 视觉观察提示词

```text
你负责从给定篮球视频证据中提取可验证的候选事件。
只使用提供的帧、时间戳和授权记录，不根据文件名认定球员身份。
帧之间发生但没有证据的动作不能补写成确定事实。
不要生成命中率、引力、胜负影响率等官方数字；没有来源就留空。

任务：
1. 按时间阅读关键帧，指出可见的关键动作，数量以证据为准。
2. 每个动作给出候选开始/结束时间、证据 frame_id、参与者临时 ID。
3. observation 只写看见的事实；interpretation 单列且可为空。
4. 标记可能的切镜、回放、遮挡、号码不清和身份冲突。
5. 无法定位的动作列入 unresolved；需要补帧时给出时间区间和原因。

输出：clip_id、candidate_events、unresolved、additional_frames_needed。
事件字段遵循本项目提供的内部数据规范。必须引用输入中真实存在的 frame_id。
没有处理成功时明确返回处理失败原因，不能以空事件列表伪装成功。
```

## B. 关键帧复核提示词

```text
你负责核对候选事件。先独立检查原始帧和官方记录，再对照候选结果。
另一模型的描述是待验证主张，不是证据；两个模型一致也不等于事实成立。

逐项检查：动作是否可见、顺序是否合理、时间是否有画面支持、球员身份是否有依据、
是否把回放当新事件、官方数值是否逐字对应源记录及单位。
对每条主张返回 accepted / needs_revision / rejected / unresolved，
给出输入中的 frame_id 或官方 record_id、问题原因与最小修正。
没有证据时不要通过；不能只因为表述流畅、符合篮球常识就接受。

输出：clip_id、claim_reviews、remaining_questions。
返回 accepted 是模型复核意见，不得改写为“人工已审核”。
```

## C. 解读与叠加文案提示词

```text
使用已经通过项目校验的事实与官方数据，生成适合短视频叠加的中文解读。
每张卡只说一个重点，避免遮住持球人和篮球。事件数量服从已验证事实。
画面事实、战术推断、官方数值分别标记；战术解释不得猜测球员主观意图。
不要把相关性写成因果，不写“必进”“决定胜负”等没有证据的断言。

每张卡返回：关联 event_id、建议显示区间、短标题、短正文、claim_type、source_refs。
官方指标缺失时保留“官方数据未提供”，不生成替代数字。
AI 生成的解释标记 ai_generated=true；文本中的任何数字必须能追溯到提供的证据。
```

## 工程复核仍然必需

模型返回后由程序检查时间范围、帧 ID、指标原值、字段类型与来源引用。未知字段、非法时间或来源断链应显示明确失败；最多一次有针对性的格式修复，不反复盲目重试。修复后的内容仍需重新校验。

只修改字体、颜色或布局时计划复用已核对分析结果；最终是否允许比赛场景缓存和人工修正仍待官方确认。提示词、抽帧策略和模型版本变更应有版本记录；先保留质量证据，再考虑压缩 token。
