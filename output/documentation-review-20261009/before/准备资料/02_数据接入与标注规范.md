# 数据接入与标注规范（内部草案 v0.1）

本规范用于本地准备；收到官方 sample 后由适配层映射。**不宣称这些字段是赛事官方 schema。** 10/09 已有两段解码视频、关键帧和[已处理数据包](../data/processed/20261009/README.md)：41 次投篮补齐官方时钟，其中两次得分与本地视频关联。独立人工参考答案与付费模型实验仍未产生；场次汇总语义冲突仍须隔离。

**当前实际文件：** [clip-events.json](../data/processed/20261009/clip-events.json)（内部 v0.2）；详见[字段字典](../data/processed/20261009/data-dictionary.md)。其中 `start_ms/end_ms` 仅为出手不确定区间，由 `time_extent` 明确限定，不能当作完整动作边界。本规范中的空值规则继续适用于未标注内容；原空模板保留。

## 1. 素材与身份

素材 ID 使用中性的 `train_001`、`train_002`，与[素材登记](表格/素材登记.csv)一一对应。文件名包含的人名和日期仅作为文件名信息，不作为已证实的球员/比赛身份。官方 `game_id`、`player_id`、`team_id` 尚未知时为 null，不以姓名字符串作为跨表主键。

原片保留在用户指定路径，不重命名。所有分析副本记录父素材 ID、原片哈希、转换设置及自己的哈希。第二段文件名在 `.mp4` 前有空格，读取时使用登记表的完整路径。

## 2. 视频时间与画面证据

- `video_time_ms`：相对当前原视频的播放时间，起点为 0；使用解码呈现时间生成，不能仅用“帧号 / 四舍五入 FPS”代替。
- `period` 为比赛节次；新数据分别使用 `official_game_clock_text`（官方记账时钟）和 `video_scorebug_clock_near_release`（画面出手附近记分牌时钟）。无法辨认则 null，不将官方时钟冒充 OCR/视觉结果，也不与视频时间线性等同。
- `shot_time_ms`：出手瞬间，允许不确定；有争议同时记录候选区间及原因。
- 每个切镜段给 `segment_id`；回放标注 `is_replay`，未知为 null。回放不是另一次真实出手事件。
- 证据帧给 `frame_id`、`video_time_ms`、相对路径；裁剪另存裁剪区域和父帧 ID。不能引用未生成的帧文件。
- 单点标记用原画面归一化坐标 `(x, y)`，原点左上、取值 0–1；框用 `[x_min,y_min,x_max,y_max]`。这些是图像坐标，不是球场米制坐标。
- 像素移动不能直接称为跑动距离、速度或官方引力；比赛给的出手点位不构成逐帧轨迹。

## 3. 事件记录的最低内容

| 字段 | 规则 |
| --- | --- |
| `event_id` / `event_type` | 本地唯一 ID；类型建议 pass、drive、shot、screen、other、unknown，不强凑三种动作 |
| `clip_id` / `source_sha256` | 必须对应素材登记 |
| `start_ms` / `end_ms` | 非负，起点不晚于终点，终点不越出素材范围 |
| `evidence_frame_ids` | 至少一个真实帧；时间动作应包含先后画面证据 |
| `observation` | 只写画面可见事实，注明遮挡或不确定之处 |
| `interpretation` | 与事实分开，允许为空；推断使用审慎语言，不猜心理动机 |
| `entities` | 临时画面 ID 与官方球员 ID 分开；身份未确认则 `player_id=null` |
| `official_metrics` | 无真实记录时为空数组；禁止填示例百分比或模型估算值冒充官方数据 |
| `review_status` | pending、accepted、needs_revision、rejected；必须有 reviewer 和依据才能 accepted |
| `ai_generated` | 实际使用 AI 生成的内容标 true；未处理空容器为 null |

[事件记录待填.json](表格/事件记录待填.json)是空容器。`events=[]` 配合 `processing_status=not_started` 意味着该模板“尚未分析”，不是“没有动作”。当前进度应读实际 `clip-events.json`；模板没有用假篮球事件填充。

## 4. 官方指标怎么接入

先填写[字段映射](表格/字段映射.csv)。接入时保留官方原始字段名和原始值，再确定显示用字段；不得让模型自由拼表。

每项指标至少记录：`source_file`、`source_record_id`、`source_field`、`metric_name`、`value`、`unit`、`definition_ref`、`game_id`、`official_event_id`。如来源以行定位，记录原文件哈希和行号/JSON 路径。

需要由数据字典确认的事项：

1. 预期命中率和投篮难度是否相关、如何换算；未有定义不得认为二者等价。
2. 关键度与胜负影响率的含义、范围、正负方向；缺少基准不能写“提升胜率”。
3. 持球/无球引力的单位、聚合窗口和适用球员；不把持球数值贴给无球时刻。
4. 球场坐标原点、单位、方向、半场翻转规则；没有标定不能把数据点直接画到转播画面上。
5. 比赛日期时区、节次、时钟精度、事件 ID 是否唯一，以及一次回合中多次投篮如何区分。

`0`、`null`、空字符串分别处理。比例 0–1 与百分数 0–100 按字典明确转换；保留原值、转换规则和显示值。未知范围先记 unresolved，不自行猜测合法范围或悄悄夹到 0–100。

## 5. 关联与复核

使用“比赛 ID + 节次 + 比赛时钟 + 球员/球队 + 动作证据”查找候选记录，唯一确定后保存官方事件 ID。时钟缺失、时间相近或候选不唯一时保留 unresolved，禁止按最接近的一条硬匹配。

显示数值必须能沿 `事件 → 指标 → 源记录 → 原文件` 回查；没有官方数据时界面写“官方数据未提供”。官方出手点只画在明确坐标约定的球场示意图中，叠到真实球场须另有可靠标定。

人工填写[核对表](表格/人工核对.csv)，区分待检查、通过、需修正、无法判断；视频解码成功不等于内容正确。开发者自己的复核称“开发者复核”，不能写为“独立专家金标准”。
