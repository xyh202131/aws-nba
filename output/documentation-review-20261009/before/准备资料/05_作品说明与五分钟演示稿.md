# 作品说明与五分钟演示稿（设计稿）

拟用作品名：**回合透镜**。名称尚非正式提交名称。现状：已完成资料与方案准备，未实现或部署。下面“目标”“设计”段可以用于方案说明；带待填内容的运行说明和展示话术只能在实现后据实更新。

## 可复用的项目简介

回合透镜面向篮球短视频解读：把比赛回合中的关键动作、官方深度数据和对应画面放到同一条时间线上，让观众看到一次出手发生了什么、哪些数据能够解释它。

设计目标是输入一段合规比赛视频及配套官方记录，输出带可视化标注的完整 MP4 与交互播放页。页面可以跳到关键时刻、开关标注、查看证据；画面事实、战术推断与官方数字明确区分。缺失身份或数据保留未知，不由模型填充貌似精确的答案。

技术设计采用多模态 API 生成候选事件，结合抽帧、短时定位、OCR、字段和来源校验形成可追溯时间轴。正式部署方案遵循比赛要求使用 AgentCore、AWS CDK、CloudFront，具体调用入口和产物路径以官方 sample 为准。

## 答辩准备卡

**为什么用两个模型？** 当前是候选设计：一个提取视觉事件，一个查看原始关键帧复核。要用同样本实测说明是否减少关键错误；若单模型可靠且更简单，就不强保留双模型。

**你们是否只是调用 API？** 设计中的工程工作是时间轴、回放分段、身份/官方记录关联、字段校验、统一标注与视频合成。最终答辩只讲已实现并可演示的部分。

**数字从哪里来？** 官方原文件和具体记录。模型只帮助解释；找不到记录时不展示未经证实的数值。

**能恢复所有球员的轨迹吗？** 现有规则说明深度数据只有出手瞬间点位；本作品不承诺逐帧跑动轨迹复原。

**怎样保证准确？** 不做绝对保证。展示逐条证据、核对结果、错误例和适用范围；未经独立验证不能声称大规模准确率。

**如何复现？** 最终通过 Portal 绑定的 Private repo、锁定依赖、官方统一接口和版本化输入重跑。当前这些实施证据尚未取得。
