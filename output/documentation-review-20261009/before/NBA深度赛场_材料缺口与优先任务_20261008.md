## 2. 视频实物核验

元数据来自 ISO BMFF/MP4 容器解析，不是模型推断，也不是 ffprobe 全量解码验证。视频帧率为样本数/媒体时长计算的平均值；容器时长和视频轨道时长可能因音频尾部而不同。

| 文件 | 字节数 | 容器时长 | 画面 | 平均 FPS | 视频/音频样本项编码 |
| --- | ---: | ---: | --- | ---: | --- |
| `训练_弗拉格2月1日.mp4` | 83,907,519 | 21.549 秒 | 1920×1080 | 59.940014 | `avc1` / `mp4a` |
| `训练_阿门1月4日 .mp4` | 87,308,125 | 22.895 秒 | 1920×1080 | 59.940016 | `avc1` / `mp4a` |

合计 **44.444 秒**。不能再把纪要“约 48 秒”当作这批文件的实测时长。`阿门1月4日` 后、`.mp4` 前有一个空格，后续应使用精确路径或素材 ID，避免手打文件名出错。

SHA-256：

```text

9c3e4606d04e7f79e29a112952fcf069ebab202af207af500bfbc3338bc079ce

训练_阿门1月4日 .mp4
7ec745f5f1e75b0c6d6dd27d409875f67c2ac3ab76c73f7123794c96be5aee22
```

10/08 容器证据：[video-manifest.json](output/preparation-evidence/video-manifest.json)。10/09 已进一步检查真实画面并关联两条官方得分事件，见[核对报告](NBA深度赛场_视频与事件核对报告_20261009.md)。完整解码通过，记分牌可读；音频未听审、视频来源授权仍未核实，完整切镜/全部动作标注尚未完成。

两份原视频均超过 25 MB。Nova 内联视频总请求体有大小限制，后续需压缩分析副本、传同区 S3（需后续上传授权），或抽取关键帧。展示用原片和分析副本分别保存哈希，不改原件。

## 4. 优先任务与顺序

以下为下一实施阶段的任务卡，时间是个人工作量估计，不是性能实测或自动执行安排。本轮不启动云资源、训练和平台评测。

| 顺序 | 任务 | 预计工作量 | 完成标准 |
| --- | --- | --- | --- |
| T01 | 两段真实视频的本地最小闭环与事件契约 | 工具就绪后约 1–2 小时 | 有关键帧索引、时间轴、叠字 MP4 与记录；原视频哈希不变；无云调用 |
| T02 | 读取 Portal 官方数据、sample 和队伍项目资料 | 访问具备后约 0.5–1 小时 | 把具体接口/路径/事件映射写成可执行约定，锁定 repo，不修改绑定 |
| T03 | 云端接入前核验 | 约 0.5 小时，不含配额处理等待 | 核对目标项目、区域、模型完整 ID、预算及权限；运行时付费验证需要单独授权 |
| T04 | 按官方协议实现 AgentCore、CDK、CloudFront 最小闭环 | 约 2–4 小时，依 sample 而定 | 官方输入能重跑，产物路径正确，成片与交互页可访问；部署需后续授权 |
| T05 | 事件理解、数据对齐、姓名/指标标注 | 约 3–5 小时 | 两段训练片逐项核验，所有数字有来源，未知不猜；调用需预算与授权 |
| T06 | 稳定性和呈现打磨 | 约 1–2 小时 | 无明显错标/遮挡；重试、复用、失败状态正确；锁定依赖和参数 |
| T07 | 正式考试素材处理与五件套交付 | 10/10 18:00–20:00 | 18:00–19:45 处理/核对；19:45 前冻结主要变更；20:00 前完成有效提交并保留回执 |

T02 的访问和配额问题可以与 T01 的本地准备并行推进，但不能为了补齐云环境擅自切换项目。规则中的“前两小时打通三项硬要求”应作为后续实施重点；目前完成的是准备，不是已经完成三项硬要求。

### 第一个可执行任务：T01

**当前进度：** 下方保留原任务分解。两段固定 ID 已采用 `train_001`、`train_002`；现有 PyAV 解码、抽帧及各一条主要得分核对已经完成。41 条比赛检索记录和两条实际事件已保存为[处理数据包](data/processed/20261009/README.md)，并备有叠字时间草案。下一项剩余动作是本地叠字导出与音画验收，无需重复分配 ID 或先安装 FFmpeg。

**输入：** 指定 `train_video` 目录内两段 MP4，以及本次已生成的 `video-manifest.json`。

**动作：**

1. 先确认可复用 FFmpeg/ffprobe 路径；当前未找到，若需要安装或调整环境，在下一实施阶段处理。
2. 为两段素材分配固定 ID（如 `train_flagg_01`、`train_amen_01`），引用原始绝对路径与哈希，不改原文件名。
3. 解码检查，按固定间隔生成带秒数索引的关键帧；记录切镜、回放、记分牌区域，不能把回放当新的比赛事件。
4. 从每片做一个只叠“本地流程验证”字幕的导出成片，检查声音、纵横比与起止时间；不填写尚无来源的官方数值。
5. 建立以下事件契约，再用人工核对后的少量事件填入开发样例。后续适配器负责映射到官方接口，不把自拟字段说成比赛标准。

**建议产物：** `data/manifest.json`、`data/events.schema.json`、`output/local-baseline/<clip-id>/frames/`、`overlay.mp4`、`validation.md`。这些是拟建产物，本轮尚未创建应用工程或生成 MP4。

| 字段 | 约定 |
| --- | --- |
| `clip_id` / `source_sha256` | 素材 ID 与原件哈希 |
| `event_id` / `event_type` | 本地事件 ID；传球、突破、投篮等受限枚举 |
| `start_ms` / `end_ms` | 视频时间轴，非比赛时钟；必须在视频范围内 |
| `game_clock` / `period` | OCR/官方数据结果，无法确认则 null |
| `entity_id` / `player_id` | 临时定位 ID 与官方球员 ID 分开 |
| `evidence_frames` | 时间戳和帧文件引用；观察与推断均须有依据 |
| `observation` / `interpretation` | 画面事实与战术推断分开；不编造主观意图 |
| `official_metrics` | 每项含名称、值、单位、来源、官方记录 ID；没有数据则空数组 |
| `review_status` / `review_note` | 未复核、已人工复核、存在争议；不能伪称独立金标准 |
| `ai_generated` | 供界面与片尾显式声明 AI 生成解说 |

**T01 验收：** 两片均能解码/导出；关键帧时间可回到原视频；没有伪造指标；输出可本地播放；原件 SHA-256 不变；记录实际耗时和工具版本；没有网络上传或模型调用。
