## 技术方案与契约

继续使用已有 **React + TypeScript + Vite、Node.js HTTP Agent、FFmpeg、Bedrock SDK、CDK**，具体版本以 [package.json](../package.json) 和 [package-lock.json](../package-lock.json) 为准。不为旧 Python 设计稿重写工程，也不为增加服务数量引入 Lambda、数据库或第二套编排。

最小工作流：输入 → 素材/时钟核验 → 关键帧 → 多模态观察 → 字段/证据校验 → 独立关联官方指标 → 统一标注时间轴 → MP4 与 Web。当前已实现的是其中两段已收录素材的离线部分，渲染和云交付仍待实现。

| 契约                                        | 用途与边界                                                                                     |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 工作区 `clip-events.json` 内部 v0.2         | 原视频证据；`start_ms/end_ms` 是出手不确定区间，单位毫秒，不是整段动作时长                     |
| 前端 `internal_review_not_contest_schema`   | 已收录回合导出/核验；浏览器内对照，不能导入任意跟踪 JSON 生成分析                              |
| `courtside.agent.request.v1` / `.result.v1` | 以 [shared/agent.ts](../shared/agent.ts) 为准；`time/requestedTime` 单位秒，分析资产为预览视频 |
| 官方比赛协议                                | 未取得。`/invocations` 目前返回内部结果，`/official/invocations` 明确返回 501                  |

各契约通过显式适配连接，不改名冒充同一版本。原件与预览哈希分开；不同时间单位显式转换；`interpretation` 可以为 null。`accepted` 的 AI 视觉核对不是独立人工审核；模型结果保持 `needs_review`，fixture 为 `fixture_replay`。

数据事实：两段原视频合计 **44.444 秒**；阿门 `0022500491/396`、Q3 07:25、视频约 18.035 秒、xFG 44.5%；弗拉格 `0022500701/666`、Q4 01:34、视频约 16.800 秒、xFG 51%。其余 39 条无本地视频关联。620 条赛季指标是三类不同统计表的记录总量，不能算作 620 次比赛事件。

关联键使用比赛、球员和官方事件 ID；时钟、画面、视频呈现时间分别保留。冲突字段隔离并等待语义澄清，不按文件修改时间择“最新真值”。赛季引力不替代单次回合指标，xFG 不等于识别置信度或实际命中率。

## 高质量模型与预算

优先验证多模态 API。Qwen3-VL 235B 为视觉候选，Sonnet 4.6 为同证据复核候选；是否保留双模型取决于错误率、时延与费用实测，不能提前声称准确性更高。Opus 4.8 仅为历史方案中的待核验难例候选，未确认当前项目可用。预训练 OCR/视觉组件仅在实际错例表明有必要时引入；不开展强化学习、基座训练或 GPU 大模型自部署。

10/08 个人项目只读记录显示 Qwen RPM/TPM 为 0；该结果可能变化，不代表本队赛事项目失败，也不代表现在已具备推理容量。主办方资料列出的 global Sonnet 不得直接用于当前个人环境。

## 第一个可执行任务：P01 本地标注成片

1. 输入工作区 `data/processed/20261009/clip-events.json`、`overlay-cues.draft.json` 和已登记视频；保留原件，输出到新的 `output/local-baseline/<clip-id>/`。
2. 先做 `train_002` 阿门，再复用流程处理 `train_001` 弗拉格。核验字体和 FFmpeg 编码/滤镜能力；已有抽帧能力不等于中文烧录编码已验证。
3. 使用统一标注清单记录显示区间、版位、文本、来源与 AI 声明；选蓝薄荷样式，避开记分牌、篮球及主要动作。没有可靠球员坐标时先用信息卡。
4. 两段均保留完整时长与原音轨，实际检查首帧、出手前后及末帧，听审同步，记录时长/分辨率/哈希；不新增模型数字。
5. 对齐 Web 与 MP4 的同一事件和指标，再记录完成项。当前没有执行此渲染任务，本次只整理文档。

资源到位后的第一个任务为 P02/P03：只读核对本队身份、区域、绑定仓库、官方协议与模型容量。当前离线 Agent 使用指南见 [AGENT_SKELETON.md](AGENT_SKELETON.md)。
